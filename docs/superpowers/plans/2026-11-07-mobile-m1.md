# Mobile M1 — Socle Android / iPhone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Android `.apk` and iPhone `.ipa` builds of SAKURA that show the live site full-screen, sign in through the browser and come back via `sakura://`, built by GitHub Actions and offered on the « Application » page.
**Architecture:** Same Tauri crate as desktop; desktop-only parts behind `#[cfg(desktop)]`. Native projects (`gen/android`, `gen/apple`) are generated in CI (`tauri android|ios init`), never committed — no NDK/Mac needed locally. The site tells desktop and mobile apart and only enables what each supports.
**Tech Stack:** Tauri 2.12 mobile, deep-link plugin (mobile custom scheme), GitHub Actions (ubuntu + Android SDK/NDK, macOS + Xcode), apksigner, unsigned IPA.
**Spec:** `docs/superpowers/specs/2026-11-07-mobile-apps-design.md`

## Global Constraints
- No commits. Identifier stays `app.sakura.desktop`. Scheme `sakura`, host `auth`.
- The website (no Tauri) is unchanged; the desktop app keeps every feature it has.
- Android back button: Tauri default (webview history, then close) — no custom code.

## Review Focus
- Mobile app must not call desktop-only commands (tray/autostart/presence/notify) — they don't exist there.
- Sign-in on mobile: `/auth/app` → `sakura://auth/callback` must reach the running app (cold and warm start).
- Release job must not break when Android signing secrets are missing (build unsigned, warn).

### Task 1: Site — which app am I in?
Files: `src/lib/desktop.ts`, `src/lib/app-kind.ts` (+ test), call sites (`desktop-bridge.tsx`, `app-group.tsx`, `account-menu.tsx`, `app-download.tsx`, `use-discord-presence.ts`, `presence-manager.ts`).
Produces `appKind(isTauri: boolean, ua: string): 'desktop' | 'android' | 'ios' | null` (pure, tested); `isDesktop()` keeps meaning *desktop app only*; new `isApp()` (any Tauri) and `isMobileApp()`.
- [ ] Tests: no Tauri → null; Tauri + Android UA → 'android'; Tauri + iPhone/iPad UA → 'ios'; Tauri + Linux/Windows/Mac UA → 'desktop'.
- [ ] Sign-in through the system browser + DesktopBridge auth listener use `isApp()`; everything else stays `isDesktop()`. Mobile app hides « Application » in the menu and shows « Vous utilisez déjà l'application » on /app.

### Task 2: Rust — mobile build of the crate
Files: `src-tauri/src/lib.rs`, `shell.rs`, `commands.rs`, `Cargo.toml` (desktop-only deps under `cfg(not(any(target_os="android", target_os="ios")))`), `tauri.conf.json` (deep-link `mobile`), capabilities (`platforms`).
- [ ] Desktop-only: single-instance, window-state, autostart, updater, tray, close-to-tray, presence (Discord IPC), notify loop, linux icon, `register_all`, DMA-BUF env. Mobile: main webview on the site (offline fallback page), deep links → pending slot + event, `open_external`, `take_pending_auth`, `app_version`, `retry_connection`.
- [ ] Capability `sakura-site` split: common commands for all platforms; `sakura-site-desktop` (desktop platforms) for tray/autostart/presence/notify/update commands.
- [ ] `cargo check` (desktop) + `cargo check --target aarch64-linux-android` if the target installs (no NDK needed for check of pure Rust? if linking fails, CI is the gate). `cargo test` green.

### Task 3: CI — `.github/workflows/mobile-release.yml`
- [ ] Triggers like desktop (tag `app-v*`, release published, manual with tag). Android job: Java 21, Android SDK + NDK r27, Rust android targets, `npm ci`, `tauri android init --ci`, `tauri icon public/icon.png`, `tauri android build --apk`, zipalign + apksigner with secrets (unsigned fallback with a warning), upload `SAKURA_<v>_android.apk` to the release.
- [ ] iOS job: macos-latest, Rust `aarch64-apple-ios`, `tauri ios init --ci`, `tauri icon`, `xcodebuild` Release `CODE_SIGNING_ALLOWED=NO`, package `Payload/*.app` → `SAKURA_<v>_ios.ipa`, upload.
- [ ] YAML validated.
